# Shelly Router Watchdog

Надежный watchdog для роутера на базе Shelly Plug и Shelly Script.

Проект предназначен для автономного контроля домашнего интернет-соединения и автоматического восстановления работы роутера при пропадании доступа в Интернет.

Основная цель проекта — максимальная надежность при долговременной непрерывной работе.

---

# Основные возможности

- контроль состояния силового реле Shelly;
- автоматическое включение реле при случайном выключении;
- проверка доступности Интернета через несколько независимых URL;
- повторные проверки Интернета перед принятием решения о перезагрузке;
- автоматическая перезагрузка питания роутера;
- ожидание полной загрузки роутера после подачи питания;
- ограничение частоты аппаратных перезагрузок;
- диагностика текущего состояния через объект `info`.

---

# Основные принципы

Во время разработки были приняты следующие правила.

## Простая архитектура

- один конечный автомат;
- один программный таймер;
- один объект состояния (`state`);
- один объект диагностики (`info`).

---

## Минимальная связанность

Конечный автомат не знает, какие именно URL используются для проверки Интернета.

Добавление или удаление URL не требует изменения логики проекта.

---

## Fail Safe

Если возможны несколько вариантов восстановления, всегда выбирается наиболее безопасный.

Например:

- если реле уже выключено — выполняется обычное включение питания вместо Power Cycle;
- если минимальный интервал между аппаратными перезагрузками еще не прошел — Power Cycle не выполняется.

---

## Минимальное использование памяти

Проект ориентирован на месяцы непрерывной работы.

Поэтому:

- используется `Date.now()`;
- отсутствуют анонимные функции;
- отсутствуют замыкания;
- создается минимальное количество временных объектов.

---

## Самодокументируемый код

Каждая функция выполняет только одну задачу.

Названия функций описывают действие.

---

# Архитектура

Используется один конечный автомат.

```text
STARTING
    │
    ▼
WAIT_BOOT
    │
    ▼
CHECK_POWER
    │
    ├──────── Relay OFF ───────► Power ON
    │                              │
    │                              ▼
    │                         WAIT_BOOT
    │
    └──────── Relay ON ───────► CHECK_INTERNET
                                   │
                    ┌──────────────┴──────────────┐
                    │                             │
                    ▼                             ▼
               Internet OK                 Internet FAIL
                    │                             │
                    ▼                             ▼
              WAIT_BOOT                WAIT_INTERNET_RETRY
                                                  │
                                                  ▼
                                           CHECK_INTERNET
                                                  │
                                         Retry limit reached
                                                  │
                                                  ▼
                                           Power Cycle
                                                  │
                                                  ▼
                                             WAIT_BOOT
```

---

# Проверка Интернета

Используется список независимых URL.

Проверка выполняется последовательно.

Первая успешная проверка завершает цикл.

Только если все URL недоступны — Интернет считается недоступным.

---

# Повторные проверки

Перед аппаратной перезагрузкой выполняется несколько полных циклов проверки Интернета.

Каждый цикл проверяет все URL.

Это значительно снижает вероятность ложных перезагрузок.

---

# Ограничение аппаратных перезагрузок

Проект различает:

- неисправность домашнего оборудования;
- длительную аварию у интернет-провайдера.

После выполнения Power Cycle следующая аппаратная перезагрузка разрешается только по истечении заданного минимального интервала.

Пока интервал не истек, watchdog продолжает регулярно проверять Интернет, но не отключает питание роутера.

Это позволяет избежать десятков бессмысленных перезагрузок при длительных авариях у провайдера и снижает износ оборудования.

---

# Power Cycle

Перед выключением питания дополнительно проверяется состояние реле.

Возможны два сценария.

## Реле включено

```
OFF
 ↓
ON
 ↓
ожидание загрузки
```

## Реле уже выключено

```
ON
 ↓
ожидание загрузки
```

Такой подход делает проект независимым от особенностей реализации `toggle_after`.

---

# Диагностика

Во время работы поддерживается объект `info`.

Он содержит информацию, необходимую для анализа работы watchdog без обращения к журналу событий Shelly.

---

# Проверенные сценарии

- запуск после подачи питания;
- запуск при выключенном реле;
- ручное выключение реле;
- отказ одного URL;
- отказ нескольких URL;
- отсутствие Интернета;
- восстановление Интернета;
- аппаратная перезагрузка роутера;
- ограничение частоты аппаратных перезагрузок;
- ожидание загрузки роутера после восстановления питания.
